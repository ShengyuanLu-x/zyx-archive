## 一、这是什么

这是一个"跨平台资料导航网站"的最简单测试版本：

- 打开网站 → 看到一个"事件"列表（按时间排序）
- 点进一个事件 → 看到这个事件相关的所有链接（微博、抖音、B站、知乎……）
- 点击某条链接 → 直接跳转到对应平台的原始页面

网站**不保存、不搬运**任何平台的内容，只是"指路牌"。

## 二、文件夹里都是什么（不用全部看懂，知道去哪改就行）

```
zyx-archive/
├── index.html          ← 首页网页（不用改）
├── event.html           ← 事件详情页网页（不用改）
├── css/style.css        ← 网站样式/颜色（不用改）
├── js/                  ← 网站的运行逻辑（不用改）
└── data/events/         ← ⭐ 你唯一需要打交道的地方 ⭐
    ├── manifest.json     ← 一份"目录清单"，列出现在有哪些事件
    ├── 2025-08-01-test-stage-a.json   ← 一个事件 = 一个文件
    ├── 2025-06-10-test-award-b.json
    └── ……
```

**日常维护资料，只需要碰 `data/events/` 这个文件夹里的文件，完全不用碰网页代码。**

## 三、一个"事件文件"长什么样

打开任意一个 `data/events/xxxx.json` 文件，你会看到类似这样的内容（这种格式叫 **JSON**，是一种非常通用的"数据记事本"格式）：

```json
{
  "id": "2025-08-01-test-stage-a",
  "title": "测试舞台 A",
  "date": "2025-08-01",
  "summary": "这是一个测试事件的简介文字。",
  "materials": [
    {
      "category": "正式内容",
      "platform": "微博",
      "title": "工作室舞台照片",
      "url": "https://weibo.com/xxxxx"
    }
  ]
}
```

对照表：

| 字段 | 含义 | 举例 |
|---|---|---|
| `id` | 这个事件的编号，建议格式是"日期-简短英文描述"，**同一个网站里不能重复** | `2025-08-01-test-stage-a` |
| `title` | 事件标题，会显示在列表和详情页 | `测试舞台 A` |
| `date` | 日期，格式固定为 `年-月-日`，用来自动排序 | `2025-08-01` |
| `summary` | 一两句简介 | ... |
| `materials` | 这个事件下面所有的链接，是一个列表 | 见下 |

`materials` 列表里每一条链接包含：

| 字段 | 含义 | 目前支持的取值举例 |
|---|---|---|
| `category` | 分组标题，决定这条链接显示在详情页的哪个板块下 | `正式内容` / `官方物料` / `当时的讨论` / `其他`（也可以自己写别的文字，会自动单独成一组）|
| `platform` | 平台名称，决定链接前面小标签的颜色 | `微博` `抖音` `小红书` `知乎` `贴吧` `Bilibili` `YouTube` `媒体`（写别的平台名也能显示，只是没有专属颜色，会用灰色）|
| `title` | 这条链接的标题文字 | `工作室舞台照片` |
| `url` | 真实网址，必须以 `https://` 开头 | `https://weibo.com/xxxxx` |

## 四、常见操作怎么做

### 4.1 新增一条链接（比如加一条新微博）

1. 打开对应事件的 json 文件
2. 在 `materials` 列表**已有的最后一条**后面，先加一个英文逗号 `,`，再照着格式加一段新的：

```json
    {
      "category": "官方物料",
      "platform": "微博",
      "title": "新的一条微博标题",
      "url": "https://weibo.com/新链接"
    }
```

3. 保存文件

> 最容易出错的地方就是这个逗号——每一条记录之间要用逗号隔开，但**最后一条记录后面不能有逗号**。这也是为什么更推荐让 AI 帮你改：AI 不会漏逗号。

### 4.2 修改已有链接（标题/网址/平台/分类）

找到对应那一条，直接把引号里的文字换成新内容即可，例如把网址改掉：

```json
"url": "https://weibo.com/换成真实链接"
```

### 4.3 删除一条链接

把对应的这一整段（从 `{` 到 `}`，包括前后的逗号处理）删掉即可。删除后注意检查：现在的最后一条后面不能留逗号。

### 4.4 调整链接顺序

`materials` 是一个列表，**列表里的顺序就是网页上显示的顺序**（同一个分类下）。想调整顺序，直接把整段内容剪切、粘贴到新位置就行。

### 4.5 新增一个"事件"

1. 复制一份现有的事件 json 文件，改名成新的文件名（建议格式：`年-月-日-简短英文描述.json`）
2. 打开新文件，把 `id`、`title`、`date`、`summary`、`materials` 都改成新事件的内容（`id` 要和文件名前面那段一致）
3. 打开 `data/events/manifest.json`，在列表里加一行新文件的 `id`（顺序不重要，网站会自动按日期排序），别忘了处理好逗号

### 4.6 删除一个事件

1. 删除对应的 `data/events/xxxx.json` 文件
2. 打开 `manifest.json`，把这个事件的 `id` 从列表里删掉

### 4.7 修改事件标题/日期/简介

打开对应事件的 json 文件，直接修改 `title`、`date`、`summary` 后面引号里的文字即可。

## 五、改完之后，网站什么时候会更新？

网站部署好之后（见下面"部署"部分），流程是：

**你（或 AI）修改文件 → 把改动"上传"到 GitHub（这一步叫 push） → 托管网站的服务会自动检测到变化 → 几十秒到几分钟内，公开网址上的内容自动更新**

你不需要手动"发布"或"上传网站"这个动作，只需要保证修改被 push 到 GitHub 即可。

## 六、名词小词典

- **GitHub**：一个存放代码/资料、并记录每次修改历史的免费网站，相当于一个带"时光机"的云端文件夹
- **仓库（repository / repo）**：GitHub 上存放这个项目所有文件的地方，可以理解为"这个项目专属的文件夹"
- **commit**：一次"存档"，记录你这次改了什么
- **push**：把本地的改动"上传"到 GitHub 仓库
- **部署（deploy）**：把网站文件发布到互联网上，让别人能通过网址访问到
- **JSON**：一种数据记事本格式，用 `{ }` 表示一条记录，用 `[ ]` 表示一个列表

## 七、部署说明（给以后维护的人看）

这个网站部署在 **Cloudflare Workers（静态资源模式）**，通过 GitHub 仓库自动触发：

- 每次有新内容 push 到 `main` 分支，Cloudflare 会自动重新构建并发布，几十秒内生效，不需要手动操作
- 仓库根目录的 `wrangler.jsonc` 是部署配置文件（说明"哪个目录是网页文件"），一般不需要改动
- `.assetsignore` 用来告诉部署系统"哪些文件不要发布出去"（比如 `.git` 内部数据），新增需要保密的文件时可以加进这个列表
- 如果想在 Cloudflare 后台看部署记录/网址：登录 [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → 找到 `zyx-archive` 项目
